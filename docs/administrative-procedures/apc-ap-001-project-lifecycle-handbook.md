# APC Project Lifecycle Handbook

**Procedure ID:** APC-AP-001

[← Back to documentation index](../index.md)

---

## 1. Purpose

The purpose of this handbook is to establish the Advanced Practices Council (APC) Project Lifecycle and provide a standardized framework for how analytics initiatives, data products, reporting solutions, semantic models, and governed analytics assets are requested, designed, developed, delivered, deployed, supported, enhanced, and retired.

This framework provides a consistent operating model for:

- Data Engineering (DE)
- BI Analytics (BI)
- Business Stakeholders
- APC Representatives
- Practitioners
- Analytics Leadership

The APC lifecycle promotes consistency, governance, quality, supportability, and scalability across enterprise analytics initiatives.

## 2. Scope

This handbook applies to all APC-governed assets including:

#### Data Assets

- Data Pipelines
- Data Products
- Lakehouses
- Warehouses
- Tables
- Views

#### Analytics Assets

- Semantic Models
- Reports
- Dashboards
- Scorecards
- KPI Frameworks

#### Governance Assets

- KPI Definitions
- Business Glossary
- Documentation
- Metadata
- Lineage Records
- Naming Standards

#### Practitioner Assets

Assets seeking APC certification, promotion, publication, or enterprise support.

## 3. APC Lifecycle Overview

The APC lifecycle consists of eight phases:

| **Phase** | **Purpose** |
| --- | --- |
| Discovery / Define | Evaluate, classify, scope, prioritize and approve work |
| Design | Create business, technical, governance and architecture requirements |
| Develop | Build approved solutions |
| Deliver | Validate and obtain business approval |
| Deploy | Release approved solutions into production |
| Operate | Support and maintain production assets |
| Enhance | Implement approved changes and improvements |
| Retire | Decommission assets that are no longer required |

## 4. Lifecycle Guiding Principles

#### Governance Before Scale

Assets promoted into enterprise use must adhere to APC standards.

#### Enablement Over Control

The APC exists to enable analytics adoption and self-service analytics while maintaining trust and consistency.

#### Ownership Must Be Clear

Every APC-governed asset must have defined ownership.

#### Documentation Is Part of the Product

Documentation, metadata, glossary terms, lineage, and KPI definitions are required deliverables.

#### Standards Drive Consistency

Naming standards, architecture standards, modeling standards, certification requirements, and governance processes should be applied consistently.

## 5. Lifecycle Phases

#### Phase 1 – Discovery / Define

#### Objective

Understand business need, classify work, define scope, determine ownership, assess value, and establish prioritization.

#### Key Outputs

- Intake Request
- Discovery Notes
- Business Requirements
- Initial Scope
- Priority Assignment
- Charter (if required)

#### Exit Condition

Request is approved and ready for Design.

#### Phase 2 – Design

#### Objective

Define business, technical, governance, architecture, security, and data requirements.

#### Key Outputs

- Project Resource Assignments
- BRD
- Technical Specifications
- Architecture Design
- Data Model Design
- Security Design
- Testing Approach

#### Exit Condition

Design is approved and ready for Development.

#### Phase 3 – Develop

#### Objective

Build approved data and analytics solutions according to APC standards.

#### Key Outputs

- Data Pipelines
- Lakehouse / Warehouse Objects
- Semantic Models
- Reports
- Dashboards
- Draft Documentation

#### Exit Condition

Development complete; ready for validation.

#### Phase 4 – Deliver

#### Objective

Validate business requirements, data quality, KPI accuracy, security, and usability.

#### Key Outputs

- UAT Results
- Validation Results
- Defect Resolution
- Sign-Off Documentation

#### Exit Condition

Solution approved for production deployment.

#### Phase 5 – Deploy

#### Objective

Promote approved assets into production and transition to operational support.

#### Key Outputs

- Production Release
- Deployment Validation
- Release Documentation
- Voice of Customer Feedback
- Hypercare Plan

#### Exit Condition

Asset successfully operating in production.

#### Phase 6 – Operate

#### Objective

Manage, support, monitor, and govern production assets.

#### Key Outputs

- Operational Metrics
- Support Records
- Incident Records
- Data Quality Reviews
- Adoption Metrics

#### Exit Condition

Asset remains operational until enhancement or retirement is initiated.

#### Phase 7 – Enhance

#### Objective

Manage changes, improvements, and optimization of existing assets.

#### Key Outputs

- Enhancement Requests
- Updated Requirements
- Updated Solutions
- Updated Documentation

#### Exit Condition

Enhancement completed and asset returned to Operate.

#### Phase 8 – Retire

#### Objective

Safely remove assets that are obsolete, replaced, unused, or no longer aligned with APC standards.

#### Key Outputs

- Retirement Approval
- Archive Records
- User Notifications
- Catalog Updates

#### Exit Condition

Asset formally retired and documented.
